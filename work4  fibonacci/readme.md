首先查看输入范围，n<=100，由于斐波那契函数的增长速度类似2^n，这说明需要输出的最大可能性的数值会达到大约2^100(十进制有21位)


为了便于计算与输出，就不直接使用二进制进行存储与计算，而是直接使用单个字节存储一位十进制数字，每个数字最多需要21个字节(代码中使用22个字节，其中最前面的一位代表当前f_n是否已被计算)


为了输入方便，直接使用int21h，ah=0A的读取到缓冲区功能，
需要在data数据段以input_buf db 6, 0, 6 dup('$')格式进行缓冲区的定义
第一个位置代表当前允许输入的最大长度(注意此处由于使用db进行存储，最大值为255)
第二个位置代表当前接收到的数据的真实长度
第三个位置及以后才是真是读到的数据(ascii码)
注意：读到的数据区中会包含最后输入的回车，但是第二个位置中统计的数值不包含该回车

调用乘法时忘记mul会将dx进行更改，所以需要将乘数10安置在其他寄存器中

使用mov  si,input_buf+2 会报错Operand types must match，这说明系统误认为这是在读取里面的数据，使用lea则可以正常获取到对应的指针


递归的时候，使用栈进行参数传递


第一次运行时，在第101行 mov  byte ptr cl,ds:[bx] 发生报错：Illegal use of register，查询资料后，得知问题是：byte ptr 只能修饰内存，不能修饰寄存器，当前语句已经说明使用的是cl这个8位寄存器，所以不需要使用byte ptr对其修饰


第二次运行时，发现输入2就会出现卡死的情况，重新检查函数后，发现fib_fun检查"是否已计算"的偏移计算错误，由于忘记了fib(0)的存在，导致多减了22，在判断fib(0)时会发生溢出

修正完成第二次检查出的问题后，发现输出乱码，检查输出函数，发现依旧是由于偏移计算错误，正确的fib(n) 的数值范围是：n*22 + 1 到 n*22 + 21 ，结果输出的是 di = n*22 - 1 到; si = n*22 - 22,修改后能正常输出答案


再计算栈总共需要的大小,call指令压入1个返回地址(2字节),push bp压入1个旧 BP(2字节)，push ax/bx/di/si 压入 4个字(8字节)。所以每层递归固定占用 12 字节。
算 fib(100) 时，由于是自顶向下递归(先算 n-1，再算 n-2)，最深的一条路径是 100->99->98 ->··· ->1,也就是深度可达 100 层。
最大栈需求大概是 100×12=1200 字节。

c语言版本基本结构类似，并且由于不需要维护栈，更简单，可以直接使用二维数组进行实现
