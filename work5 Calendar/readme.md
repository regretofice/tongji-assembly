要实现的是月历的打印，首先可以直接将上次的输入逻辑提取成get_num，这个过程，可以直接读取最多4位数字，并将结果存储到ax寄存器中，

由于本次作业要求使用两个代码段，所以决定将输入输入/计算进行隔离，将计算的过程放在另一个代码段中，

关于具体的计算，查询到可以使用Sakamoto算法进行快速计算，


第一次尝试运行时，发现会报错错误: Missing or unreachable CS，

发现问题是在顶部的assume处，同时声明了两处cs地址：  assume cs:code, cs:calendar,
将这两处分别放置在段内而不是外部，就可以正常通过编译了
经过搜索，发现声明在段内外的差异是：就像 C 语言里的花括号 {}。在段内声明，是在告诉汇编器：“在当前这个作用域内，代码段基址对应的是我”。它解决了多段程序在编译期的上下文归属问题。

第二次尝试运行时，发现换行逻辑不正确，无法正确进行换行
检查代码后，发现是完全无法进入endl这个标签中
在仔细调试+询问ai之后，才发现问题源自于print_blank这个过程，里面调用了int 21h中断，会改变ax的值，原本的di就不会存储已经输出的数量了

解决完换行问题后，发现输入2026 11，之后，1号被放置在周六，输入2027 3之后，会先跳出一堆换行，在输出一个错误的日期

最终发现，是由于之前的shift表放置在calendar段内，而不是data段内，而Sakamoto中进行的ds设置失效了，无法直接更改ds的值，所以在不变动ds的值的情况下就能够正常计算了

本次实验说明，所有数据应当全部存储在同一个数据段，不应当在运行中更改ds的值
并且在处理两个不同段的代码时，需要额外写far标签，使得cs与ip一同进行跳转
